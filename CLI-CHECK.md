# Проверка Дня 18 через консоль

То же, что `MANUAL-CHECK.md`, но без браузера. Проверяются четыре пласта:

* **новое в Дне 18** — планировщик: задание ставится в расписание и переживает
  процесс, отдельный работник выполняет его без человека, история копится, а
  сводка отвечает на вопрос «что изменилось, пока меня не было»;
* **наследство Дня 17** — свой MCP-сервер вокруг API трекера: вызовы руками и
  моделью, заявка на всё, что меняет чужие данные;
* **наследство Дня 16** — подключение MCP как таковое: список серверов,
  соединение по stdio и HTTP, фильтр, понятные сбои;
* **наследство Дней 11–15** — слои памяти и разбор промпта, заготовки профиля,
  пауза, инварианты с отказом за ноль токенов, ворота переходов и диалоговый
  режим.

Мок-трекер поднимает сам скрипт прогона — на свободном порту и со своими
данными в `cli-check-memory/tracker-data.json`. Работника он тоже запускает сам,
там, где это нужно по шагу. Руками запускать ничего не нужно.

```bash
cd ~/Документы/AI-Advent-Challenge/Day-18
.venv/bin/python check_cli.py                # весь чек-лист + отчёт в CLI-CHECK-RESULTS.md
.venv/bin/python check_cli.py --без-модели   # без живых вызовов модели
.venv/bin/python check_cli.py --в отчёт.md
```

Ниже вместо `.venv/bin/python` написано просто `python`: так короче, а с
активированным окружением (`source .venv/bin/activate`) это одно и то же.
Команды с `$ФАЙЛ` подразумевают файл серверов прогона
(`cli-check-memory/mcp-configs/scheduler.json` для планировщика,
`…/tracker.json` для трекера); вручную то же самое делается с
`mcp-servers.json`, если в соседнем терминале поднят `python tracker_api.py`.

## Часть 3. Планировщик глазами модели

Эта часть требует живого ключа: модель сама решает позвать планировщик.

**3.1. Модель ставит задание**

```bash

              "Поставь в расписание планировщика сбор задач очереди MIG каждые 30 минут — \
               инструмент tracker__list_issues с аргументом queue=MIG."
```

- [ ] Под ответом строка «↳ scheduler__schedule_job(...) — N,N с».
- [ ] Заявки нет: расписание — собственная память агента.

**3.2.** `python cli.py --задания` — задание от модели в расписании.

**3.3. Планирование изменения требует подтверждения**

```bash

              "Запланируй через минуту добавить к задаче MIG-7 комментарий
               «смотрю за миграцией» — поставь это в расписание планировщика."
```

- [ ] Вызова не было, появилась заявка на `scheduler__schedule_job`, и агент
      просит подтвердить.

**3.4.** `python cli.py --заявки` — в аргументах заявки видно
`tool: tracker__add_comment`: что именно будет вызвано потом.

**3.5.** `python cli.py --отклонить 1 --почему «проверка»` — «вызов не делался»,
задания в расписании не появилось.
